자체 서빙 모델 콘텐츠 필터

자기회귀 모델의 "생성 관성"을 역이용해 응답 전에 분류를 강제하는 2-Step 기법으로 F1을 18.1%에서 87.0%로 올렸습니다.

  • 기간2026.06 (1개월)
  • 소속(주)버블탭 AI코어팀
  • 역할단독 기획·설계·개발
사용 기술

Prompt EngineeringChain-of-ThoughtvLLMPythonGemini(데이터 검증)

문제#

자체 서빙 모델은 상용 API와 달리 플랫폼 수준의 콘텐츠 필터가 없어, 안전장치를 직접 만들어야 했습니다.

  • 필터가 없으면 미성년자 대상 성적 콘텐츠가 생성될 수 있음
  • "생성하지 마시오" 수준의 단순 지시는 거의 무효: Baseline F1 18.1%, Recall 10.0%
  • 법적·윤리적 리스크 대응과 서비스 안정성 확보가 시급함

Recall 10%는 걸러야 할 열 건 중 아홉 건이 그대로 나간다는 뜻입니다.

접근법 선택#

  • Fine-tuning: 학습 데이터 구축 비용이 크고 실험 사이클이 깁니다
  • 외부 분류기: 추가 인프라와 지연이 붙습니다
  • 프롬프트 엔지니어링: 즉시 배포할 수 있고 실험 사이클이 짧습니다 ← 1차 접근법으로 선택

시급한 만큼 가장 빨리 돌려볼 수 있는 방법으로 상한을 확인하고, 부족하면 다음 수단으로 넘어가기로 했습니다.

핵심 기법: Think First, Flag Next#

자기회귀 모델은 생성을 시작하면 관성으로 멈추지 못합니다.
반대로 생성 전에 판단을 끝내면 그 관성이 안전한 방향으로 작동합니다.

유저 입력 + 캐릭터 프로필
    │
    ▼
① Flag 분류
    응답의 첫 토큰으로 MINOR / ADULT / SAFE 강제 출력
    │
    ▼
② Chain-of-Thought
    1. 캐릭터 나이 판정
    2. 프로필·입력의 성적 요소 확인
    3. 최종 판정
    │
    ▼
응답 생성 / 차단

방법 1. Flag 분류: 생성 전 판단 고정#

baseline ~ v4에서 자연어 지시, 수도코드, 용어 정규화, 필터 위치 변경을 시도했지만 Recall은 8~10%에 머물렀습니다.
모델이 지시를 인식은 하지만, 응답을 쓰기 시작하면 콘텐츠 흐름에 끌려갔습니다.

그래서 응답의 첫 토큰으로 분류 태그를 강제했습니다.

응답 형식:  <flag>{MINOR|ADULT|SAFE}</flag> [응답 본문]
  • 사고 강제: 생성 전에 콘텐츠 성격을 먼저 판단하게 됩니다
  • 커밋 효과: <flag>MINOR</flag>를 출력한 모델은 뒤따르는 토큰에서 차단 메시지를 낼 확률이 올라갑니다

다만 첫 토큰에 즉답해야 해서, 나이가 프로필에 간접적으로만 드러나는 경우는 판단하기 어려웠습니다.
v5의 Recall은 20.7%였습니다.

방법 2. CoT: 즉답 부담 완화#

판정할 시간을 주기 위해, Flag를 내기 전에 <think> 블록에서 구조화된 추론을 하도록 했습니다.

<think>
[CHARACTER AGE CHECK]
- Character A: "17세 고등학생"  → MINOR
- Character B: "대학교 3학년"    → ADULT

[SEXUAL/VIOLENT CONTENT CHECK]
Character profile contains sexual settings: YES
User input contains sexual/violent content: YES
Combined assessment: YES

[DECISION]
MINOR + sexual content → MINOR
<flag>MINOR</flag>
</think>
Minor character detected. Content cannot be generated.
  • CHARACTER AGE CHECK: 등장 캐릭터 전원의 나이를 ADULT/MINOR로 명시 판정합니다
  • SEXUAL/VIOLENT CONTENT CHECK: 프로필과 사용자 입력 양쪽을 봅니다
  • DECISION: 두 결과를 조합해 최종 Flag를 냅니다

가장 효과가 컸던 것은 프로필 스캔 강제(v8) 입니다.
Character profile contains sexual settings: YES/NO 체크로, 프로필에만 성적 설정이 있고 입력은 일상적인 경우까지 잡혔습니다.
성인 콘텐츠(clean 모드) 차단율을 가장 많이 올린 단일 변경입니다.

방법 3. Flag Inside Think (v14)#

v14에서 <flag>를 </think> 뒤에서 <think> 블록 안 [DECISION] 아래로 옮겼습니다.

  • 후처리 단순화: <think> 블록만 지우면 flag도 함께 사라져 사용자 응답에 태그가 남지 않습니다
  • 성능 유지: F1 87.0%로 v8(86.9%)과 동등합니다

DECISION의 상세도는 성능을 좌우했습니다.
v13에서 한 문장으로 줄이자 F1이 80.2%로 떨어졌고, 세 문장으로 되돌린 v14에서 회복됐습니다.

보조 기법#

  • Primacy Effect: 필터 모듈을 시스템 프롬프트 최상단에 배치했습니다 (v6)
  • 다국어 few-shot: 한·일·중·태 BLOCK/SAFE 예시로 다국어 감지력을 확보했습니다 (v6). v11에서 영어 예시만 남기자 clean 감지가 약해져 되돌렸습니다
  • MINOR / ADULT 필터 분리 유지: 미성년자 보호와 성인 콘텐츠 제한을 별도 모듈로 두었습니다

최종 프롬프트는 clean 모드에 두 모듈(미성년자 보호 + 성인 콘텐츠 제한), adult 모드에 한 모듈(미성년자 보호)을 적용합니다.
각 모듈에는 CoT few-shot 예시, 다국어 미성년자 감지 기준, 차단 절차, 필수 출력 형식이 들어 있습니다.

300건 테스트셋, 동일 추론 설정(temperature 1.0, top_p 0.95) 기준입니다.

핵심 발견#

높은 차단율의 착시#

v6에서 미성년 건(clean 모드) 50건 중 35건이 차단됐지만, <flag>MINOR</flag>로 차단된 건은 0건이었습니다.
전부 성인 콘텐츠 필터가 간접적으로 걸러낸 것이었습니다.

실제 미성년 감지 능력은 17% 에 불과했고, 그 안전망이 없는 adult 모드가 진짜 위험 지점이었습니다.
이후로는 어느 경로로 차단됐는지까지 나눠 봤습니다.

CoT가 고친 약점#

v7에서 CoT를 넣자 모델이 <think> 안에서 나이를 확인한 뒤 <flag>MINOR</flag>를 내기 시작했습니다.
adult 모드의 미성년 차단율이 17/50 → 45/50으로 약 2.6배 올랐습니다.
가장 약했던 영역에서 가장 크게 개선됐습니다.

성능을 좌우한 추론 순서#

v9에서 "성적 판단 먼저 → 나이 확인"으로 순서를 뒤집자 F1이 24.3%p 하락했습니다(86.9% → 62.6%). 나이 판정이 먼저 확정돼야 뒤의 판단 기준이 섭니다.
CoT는 무엇을 어떤 순서로 생각시킬지가 설계 대상임을 확인했습니다.

통합보다 분리 구조#

v10에서 토큰을 줄이려고 두 필터를 하나로 합치자 F1이 86.9% → 79.9% 로 떨어졌습니다.
두 판단은 기준이 달라 한 모듈에서 서로를 흐립니다.
분리 구조를 유지했습니다.

별개 능력인 분류와 출력 제어#

clean 모드에서 성인 콘텐츠를 차단 메시지 대신 fade-to-black(암전) 으로 넘기려 했습니다.
분류는 잘 됐지만(v12에서 28건 정확히 분류) 출력 제어가 되지 않았습니다.

시도지시 방식완전 성공
v12추상적 지시: "암전하라"0 / 28건
v15금지 목록 제약: "~하지 마라"0 / 19건
v15b행동 지시: "빠르게 넘기고 다음 상황으로 가라"8 / 20건

모델은 올바르게 분류하고도 성적 묘사를 이어서 생성했습니다.
"하지 마라"를 "하라"로 바꾼 v15b에서 처음 의미 있는 결과가 나왔지만, 감지율이 66% → 40%로 떨어져 배포하지 않았습니다.
감지와 출력 제어를 분리하는 구조가 필요하다는 결론을 남겼습니다.

평가 데이터셋 직접 구축#

3단계 필터링 파이프라인#

실서비스 데이터 499,397건에서 300건 테스트셋을 뽑았습니다.

단계방법통과
원본실서비스 대화 로그499,397건
1차규칙 기반: 키워드 프리필터 · 페르소나 나이 분석 · 성적/폭력 키워드 매칭54,514건
2차LLM 검증 (gemma-4-26b)6,363건
3차LLM 정밀 검증 (gemini-3.5-flash)4,373건
최종라벨별 샘플링 + 재검증300건

미성년 성적 100 / 성인 성적 100 / 일반 대화 100 으로 구성하고, 모드별 기대 동작이 달라 각 라벨을 일반 모드 50건과 성인 모드 50건으로 나눴습니다.
과거 회상("8세 때부터"), 세대 표기("3세"), 묘사 표현("소녀")처럼 키워드만 걸린 오탐은 걷어냈습니다.

라벨 오류 42%: 모델보다 평가셋 먼저 의심#

v7 결과를 분석하다 데이터셋 오류를 발견해 전수조사했습니다.

  • 일반 대화 100건 중 83건 라벨 오류: 성적 키워드가 있는데 일반으로 라벨링됨
  • 성인 성적 콘텐츠 100건 중 29건 불일치: 입력이 아닌 모델 출력에만 성적 콘텐츠가 있는 케이스
  • 일반 대화에 성인 모드 테스트 부재

300건 중 126건(42%) 의 라벨을 고친 뒤에야 정확한 측정이 가능해졌습니다.
성능이 정체됐다고 본 구간의 상당 부분은 정답이 틀린 것이었습니다.

부작용 검증#

출력 품질 유지#

루브릭 점수는 3.790 → 3.794 로 유의미한 변화가 없었습니다.

과잉 차단 점검#

실서비스에서 필터링된 123건을 전수 정오 분류했습니다.

구분건수비율
올바른 차단87건70.7%
의문이 있는 차단36건29.3%

의문이 남은 36건에서 과잉 차단 패턴 3가지를 찾았습니다.

유형건수판단
폭력 콘텐츠를 성인물로 오차단2건오분류: 성적 요소가 없는 액션 씬
18–19세 + 명백한 성적 콘텐츠16건시스템 기준상 정당 (기준은 별도 논의)
18–19세 + 무해한 입력12건과잉 차단: 프로필만 보고 차단
나이 추정 불확실2건과잉 차단: 나이 미명시를 미성년으로 추정
경계 사례4건케이스별 판단 필요

후속 개선 방향은 폭력과 성적 콘텐츠 분리 판단, 현재 턴 기준 판단, 나이 미명시 시 차단 기준 명확화입니다.

결과#

  • 미성년자 성적 콘텐츠 차단 F1 18.1% → 87.0% (Recall 10.0% → 84.7%, Precision 89.4% 유지, Accuracy 54.7% → 87.3%)
  • 루브릭 3.790 → 3.794로 출력 품질 저하 없음을 확인하고, 양 서비스 QA 전원 확인 후 배포
  • 배포 후 콘텐츠 필터 관련 문의 접수 0건
  • CoT로 인한 응답 지연은 3~5초로, 함께 쓰는 외부 모델(5~10초)보다 빨라 체감 영향 없음
  • 실험 과정을 논문 형식("Think First, Flag Next")으로 정리해 사내 공유

남은 한계#

  • 일반 모드 성인 콘텐츠 차단율 66%: 34%가 여전히 통과합니다
  • 성인 모드 과잉 차단 24%: 막지 않아야 할 12/50건을 막았습니다
  • 프로필 기반 과잉 차단: 프로필에 성적 설정이 있지만 입력은 무해한 12건입니다
  • 세밀한 출력 제어는 프롬프트의 한계 밖: 감지와 출력 제어를 분리하는 구조가 필요합니다
  • 필터 프롬프트 1,736 토큰: 매 요청에 실리며, fine-tuning으로 내재화하면 걷어낼 수 있습니다
  • 외부 소형 분류기 하이브리드: 성인 콘텐츠(clean) 차단율을 85% 이상으로 올릴 여지가 있습니다

한 달 안에 배포 가능한 수준까지 올렸고, 다음 수단(fine-tuning · 외부 분류기)이 해결해야 할 문제를 수치로 특정했습니다.
